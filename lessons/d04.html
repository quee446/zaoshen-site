表格与表单

今天做两件「有结构」的事：用表格展示数据，用表单收集用户输入。 表单是前端和后端握手的地方，也是面试高频考点。

⏱ 约 120 分钟 📄 产出 form.html 🎯 难度 ★★☆

一、表格 table / tr / th / td

表格是「行 × 列」的结构，四个标签分工明确：

标签含义记忆法
table整张表table = 桌子
tr一行（table row）row = 行
th表头单元格（table header）字会加粗居中
td普通单元格（table data）装数据
 



  
    

      姓名
      年龄
    

  
  
    

      小明
      20
重要观念：表格只用来展示数据。 用 table 做页面布局是二十年前的老做法，现在一律用 CSS（Flex / Grid）。 面试问到「能不能用 table 布局」要明确说不能，并说出理由：语义错误、响应式困难、代码臃肿。

二、表单 form 的作用

form 是收集用户输入的区域。用户填完点提交， 浏览器会把里面所有控件的值打包，发给 action 指定的地址。 





  ...
面试点：method="get" 参数拼在 URL 后面，适合查询； method="post" 参数放在请求体里，适合提交敏感数据。默认是 get。

三、input 的常用 type

input 是单标签，靠 type 属性变身成不同的控件：

type长什么样用途
text单行输入框姓名、昵称
email单行输入框邮箱，提交时会校验格式
password输入显示成圆点密码
checkbox方框，可多选兴趣爱好、同意条款
radio圆点，同名单选性别、学历
submit按钮提交表单

四、label 与 input 绑定

label 的 for 属性写 input 的 id， 两者就绑定了。好处是：点文字也能聚焦到输入框，手机上好点很多。
无障碍要求：每个输入框都应该有对应的 label。 读屏软件靠它念出「这个框是填什么的」。只写 placeholder 不算，因为输入内容后提示就消失了。

五、下拉框 select 与多行文本 textarea
完整报名表结构：form 里每一组「label + 控件」用 div 包一层， 方便以后加样式。这是最标准的写法。

八、口述题

面试官问：「为什么不能用 table 做页面布局？」请用 30 秒讲清楚。

看参考答案

三个理由：一，语义错误，table 是展示数据的，用它布局会让读屏软件把整页当成一张表； 二，响应式困难，表格结构僵硬，手机上很难重排； 三，代码臃肿，嵌套层级深，维护成本高。 现在布局一律用 CSS 的 Flex 或 Grid。
